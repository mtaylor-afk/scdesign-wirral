# WV Roofing: set-up and deploy (v1, 2026-09-28; updated 2026-09-29 and 2026-10-01)

## How it's hosted

WV Roofing borrows SC Design's hosting and shares nothing else with it.

- **The pages** are in `public/WVROOFING/`, served by Cloudflare Pages at
  `https://scdesignwirral.co.uk/WVROOFING/`.
- **The API** is a single Vercel function, `api/wvroofing/app.js`, on project `scdesign-wirral`.
  - `vercel.json` rewrites `/api/wvroofing/*` to it.
  - It has 300 seconds and includes the migrations (`db/wvroofing/**`).
  - `api/` holds 11 files. Never add a 12th for WV Roofing: Hobby allows 12 functions.
- **The daily tidy-up** runs at 03:17 UTC as `GET /api/wvroofing/cron/daily`, set in `vercel.json` `crons`.
- **Storage**: Neon Postgres and a private Vercel Blob store, both in London, used only by WV Roofing.
  - Migrations apply themselves on first use.
  - `/api/wvroofing/health` reports the schema version.

## Run it locally (the labelled test environment)

```
npm install                                   # once
node scripts/wvroofing/dev-server.mjs         # http://localhost:8772/WVROOFING/
```

**Stand-ins.** The dev server runs with `WVR_ENV=test`, and production refuses every one of these:

- **Database**: PGlite in memory, so data resets on a restart; `WVR_PGLITE_DIR` keeps it on disk.
- **Storage**: a local folder.
- **OpenAI**: paints the roof colour. `--fixture timeout|5xx|refused|…` tries the failure states.
- **Email**: goes to a console outbox; nothing is sent.
- **Addresses**: a street of test addresses at any postcode.
  - Ideal Postcodes' own test postcodes behave as they do there: `ID1 KFA` isn't found; `ID1 CLIP` and
    `ID1 CHOP` are unavailable.
- **Satellite view**: a drawn stand-in.

**Admin screen.** `http://localhost:8772/WVROOFING/admin/` (version 1), `/WVROOFING/2/admin/` (version 2)
and `/WVROOFING/operator/` (both). It logs in with `TEST_OPERATOR_PASSWORD` from
`serverlib/wvroofing/auth.js`, which is refused anywhere else. The three pages are generated by
`node scripts/wvroofing/gen-admin.mjs`.

**The checks (all must pass before a commit):**

```
npm run wvr:test        # node:test suites
npm run wvr:check       # JSDoc type check of the WV server code
npm run wvr:selftest    # maths, compositing and handler self-test
npm run wvr:qa          # headless browser pass (dev server running)
npm run validate        # SC's own build and checks; then: git restore -- src/lib/projects-cms.ts
npx eslint public/WVROOFING api/wvroofing serverlib/wvroofing scripts/wvroofing
```

## Going live: the owner's steps, in order

None of these involve pasting anything into a chat. Keys, secrets and the password go straight into
Vercel.

### The quick way: SET UP WV ROOFING ADMIN

Added 2026-10-01. The set-up wizard (`scripts/wvroofing/setup-vercel.mjs`) does steps 1 and 2 below, and
the enquiry email part of step 4, in one go. Only Matthew runs it; Claude never sees the token or the
password.

**How it runs.** Since 2026-10-02, **PUSH WV ROOFING.cmd** on the Desktop runs it straight after a
successful push, in the same window, until it has finished once (the last line of
`C:\dev\_wvroofing-src\setup-result.log` says `RESULT=OK`); after that, pushes skip it. Typing **S** at its
first question skips it for that push. **SET UP WV ROOFING ADMIN.cmd** runs the wizard on its own, without
pushing, for a re-run later (for example to change the admin password).

**Before you start**

- The push comes first (PUSH WV ROOFING does that), so the admin pages exist and the redeploy picks up
  the newest code.
- Make a Vercel token at `https://vercel.com/account/tokens`: **Create Token**, Scope = the team that owns
  scdesign-wirral, Expiration = 1 day. You can delete it afterwards.
- Step 0 below (the Node.js version) is still done by hand, once.

**What it asks for**

1. **The Vercel token**, at a hidden prompt (right-click pastes; nothing shows).
2. **Only if the project already has a `DATABASE_URL` or `POSTGRES_URL`:** whether that is WV Roofing's own
   Neon database. Answer **n** unless you're sure: it may be SC Design's, and WV Roofing must never use
   SC Design's database.
3. **Whether to make the photo store** (Enter = yes). Answer **n** only if a store called `wvroofing`
   already exists.
4. **The admin password**, twice, at hidden prompts (at least 12 characters). If one is already set, it
   asks "Change it?" first; Enter keeps it.
5. **Optionally, the inbox for enquiry emails.** Enter skips it.
6. **"Save these and redeploy the live site now?"** It lists the names it will save (never the values).

**What you still click in the browser**

- **Neon, the database (always the first time).** Only you can accept Neon's terms, so the wizard opens
  `https://vercel.com/marketplace/neon` and lists the clicks:
  - **Install** (or **Create Database**), the team that owns scdesign-wirral, **Create New Neon Account**
    if asked;
  - region **Europe (London)** (aws-eu-west-2), plan **Free**, database name `wvroofing`;
  - **Connect Project**: scdesign-wirral, **Production** and **Preview** only, **Custom Prefix** `WVR`
    (so the address arrives as `WVR_DATABASE_URL`, which WV Roofing reads first), preview branching off;
  - then press Enter in the wizard's window. It checks, and waits if Vercel is slow.
- **The photo store, only if needed.** The wizard makes it through Vercel's documented API
  (`POST /storage/stores/blob`): private, London (`lhr1`), called `wvroofing`, for scdesign-wirral. Vercel's
  REST docs don't say how to connect a store to chosen environments, so if it isn't connected by itself
  the wizard opens the team's Storage page: **wvroofing**, **Projects**, **Connect Project**,
  scdesign-wirral, **Production** and **Preview**, **Connect**. Then press Enter.

**What it changes**

- It saves these on scdesign-wirral, encrypted, for Production and Preview:
  - `WVR_SESSION_SECRET` (64 random hex characters) and `CRON_SECRET` (a random string), only if they're
    missing;
  - `WVR_OPERATOR_PASSWORD_HASH`, the `scrypt:` hash of the password (never the password);
  - `WVR_LEAD_TO` and `WVR_CAP_ENQUIRY_DELIVERY=on`, only if you gave an inbox.
- It redeploys production from GitHub `main`, waits until Vercel says Ready (up to 6 minutes, with dots),
  then reads `https://scdesign-wirral.vercel.app/api/wvroofing/health` and says, in plain words, what's
  set up and whether photos and enquiries are now being saved.
- It ends with the two admin addresses.

**What it never does**

- It never prints, saves or sends the token, the password, the hash or the secrets anywhere but to Vercel.
  It reads only the **names** of the project's variables, never their values.
- It never replaces an existing secret. `--rotate` replaces both secrets on purpose.
- It never touches SC Design's variables, and never asks for the email login (`SMTP_USER`, `SMTP_PASS`).
  Enquiry emails only go out once those are on the project; it says whether they are.
- If the database or the photo store isn't connected, it stops before saving anything else.

**Running it again** is safe: it only adds what's missing, and asks before changing the password. To see
what it would do without changing anything, run it in a terminal from the repository folder:

```
node scripts/wvroofing/setup-vercel.mjs --dry-run
```

**The result log.** Each run adds one line to `C:\dev\_wvroofing-src\setup-result.log`: the time and a
result code, nothing else. Claude can read it to see how the run went.

| Code | What it means | What to do |
|---|---|---|
| `OK` | Saved, redeployed, and the live site says photos and enquiries are being saved | Log in to an admin address |
| `DRY_RUN` | A dry run finished; nothing was changed | Run it without `--dry-run` |
| `NO_TOKEN` | Nothing was pasted | Run it again |
| `TOKEN_REFUSED` | Vercel didn't accept the token | Paste it in full, or make a new one |
| `NO_PROJECT_ACCESS` | The token can't see scdesign-wirral | Make a token whose Scope is the team that owns it |
| `NETWORK`, `VERCEL_ERROR` | Vercel couldn't be reached, or answered with an error | Check the internet or VPN; try again in a minute |
| `NEEDS_NEON` | The database isn't connected; nothing else was changed | Connect Neon as above (Custom Prefix `WVR`), run it again |
| `NEEDS_BLOB` | The photo store isn't connected; nothing else was changed | Connect `wvroofing` as above, run it again |
| `BLOB_NOT_PRIVATE` | Vercel made the store, but not private in London | Delete that store in Vercel, run it again |
| `PASSWORD_NOT_SET` | No usable password after three tries; nothing was changed | Run it again |
| `CANCELLED` | You answered no at the end, or pressed Ctrl+C | Run it again when ready |
| `ENV_WRITE_FAILED` | Vercel didn't save a variable (any before it were saved) | Run it again |
| `DEPLOY_FAILED`, `DEPLOY_TIMEOUT` | The redeploy failed, or took over 6 minutes; the settings are saved | Check Vercel, Deployments; run it again (press Enter at "Redeploy the live site now?") |
| `NEEDS_PUSH` | Redeployed, but GitHub `main` doesn't have the admin pages yet (they weren't pushed first) | Run **PUSH WV ROOFING**, then run this again |
| `NOT_LIVE_YET` | Redeployed, but `/health` says saving is still off | Tell Claude |
| `HEALTH_UNREACHABLE` | `/health` couldn't be read | Open it in a browser in a minute |
| `NO_TERMINAL` | It wasn't run in a terminal window, so it couldn't hide what you type | Double-click the Desktop file |
| `NO_NODE`, `NO_SCRIPT` | Written by the Desktop file: Node.js, or the script, is missing | Tell Claude |
| `ERROR` | Something unexpected | Tell Claude "set-up stopped" |

The steps below are the same work done by hand, kept as the fallback.

### By hand

**Step 0: Vercel checks.** In project `scdesign-wirral`, go to **Settings**.

- Note the plan (Hobby or Pro), whether **Fluid compute** is on, and the **Function Region**.
- Set **Node.js Version** to **24.x**: Vercel deprecates Node 20 on 1 October 2026.

**Step 1: storage.**

1. **Storage → Create → Blob**:
   - name `wvroofing`, access **Private**, region **London**;
   - connect it to Production and Preview.
2. **Marketplace → Neon**:
   - free plan, name `wvroofing`, region **Europe (London)**;
   - connect it to scdesign-wirral for Production and Preview, with **Custom Prefix** `WVR`, so the address
     is `WVR_DATABASE_URL`. The project is shared with SC Design: never point WV Roofing at SC Design's
     database.

**Step 2: core variables** (Production), then **Redeploy**.

| Variable | What to put | How to make it (on your own computer) |
|---|---|---|
| `WVR_SESSION_SECRET` | 64 random hex characters | `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `CRON_SECRET` | Another random string | The same command again |
| `WVR_OPERATOR_PASSWORD_HASH` | The `scrypt:…` line | `node scripts/wvroofing/operator-hash.mjs` (see `operator-guide.md`) |
| `WVR_LEAD_TO` | The inbox for enquiry emails | n/a |
| `WVR_MAIL_FROM` (optional) | An alias on the iCloud account that names "WV Roofing" | n/a |
| `WVR_DAILY_BUDGET_USD` | `5` | n/a |

**Step 3: pushing.** A2–B4 were pushed on 2026-09-29, ahead of steps 1 and 2, so push gate D17 no longer
holds anything back. Until storage is connected, the live visualiser works with the sample houses and quick
previews only:

- choosing your own photo says uploading "isn't available right now";
- the enquiry forms say enquiries aren't being collected yet, and nothing is sent or stored.

No further push is needed for storage: it switches on once steps 1 and 2 are done and Vercel has
redeployed. Push later work with the Desktop **PUSH WV ROOFING.cmd**:

- it fetches, rebases, and pushes `HEAD:main`;
- you paste the GitHub token when it asks; Claude never types tokens;
- never force-push.

Then run the live checks below.

**Step 4: switch on one capability at a time.**

A key alone turns nothing on. Each capability also needs its switch set to `on`, and its rights resolved in
`permissions.js`. That is recorded in `permissions-record.md`.

| Capability | Key(s) | Switch |
|---|---|---|
| Enquiry emails | `WVR_LEAD_TO` (and the existing `SMTP_USER`/`SMTP_PASS`) | `WVR_CAP_ENQUIRY_DELIVERY=on` |
| Address search | `WVR_IDEAL_POSTCODES_KEY` (set a daily lookup limit in their dashboard) | `WVR_CAP_ADDRESS_LOOKUP=on` |
| Satellite view | `WVR_GOOGLE_MAPS_STATIC_KEY` and `WVR_GOOGLE_MAPS_SIGNING_SECRET` (URL signing on, a daily quota and a budget alert) | `WVR_CAP_AERIAL_DISPLAY=on` |
| Photo-real renders | `WVR_OPENAI_API_KEY`, from a "WV Roofing concept" project with a hard monthly budget | `WVR_CAP_IMAGE_GENERATION=on` |
| Roof measurement (the roofer's own, shown once approved) and customers' plans and drawings | none beyond storage | `WVR_CAP_ASSISTED_MEASUREMENT=on` |

Photo uploads and enquiry storage come on by themselves once Neon, Blob, `WVR_SESSION_SECRET` and
`CRON_SECRET` are all present.

**Step 5: A8, live integration.** Tell Claude which keys are in, and OK the spend. Claude then runs:

- the render benchmark (at most 16 renders, about $3);
- pre-rendering the sample houses (at most 24 renders, about $2–3);
- one real enquiry email, flagged before it's sent.

## After every push: live checks

1. The Cloudflare Pages and Vercel deployments are green.
2. `https://scdesign-wirral.vercel.app/api/wvroofing/health` shows:
   - `environment: "production"`;
   - schema version 8 (`null` until the database is connected);
   - the expected capability states;
   - no secrets.
3. `https://scdesignwirral.co.uk/WVROOFING/` loads with `X-Robots-Tag: noindex` and the content security
   policy.
4. SC Design's home page returns 200, and one SC API still works.
5. `node scripts/wvroofing/qa.mjs --base https://scdesignwirral.co.uk --live`. On a deployed copy it
   fills in the enquiry forms but never sends them, makes no renders and doesn't log in to the admin
   screen. The one test photo it uploads is deleted again at the end. It reads `/health` first and checks
   what that copy has switched on: without storage, it checks the "isn't available" message instead of
   uploading. Whatever it can't run is listed as SKIP, with the reason.
6. Once storage is live, a smoke test on the live site: a sample photo, mark the roof, a render only if
   allowed, then **Delete my photo and project**.
7. Matthew logs in to `/WVROOFING/admin/` (or `/WVROOFING/2/admin/`) himself. The **Overview** tab's
   **Set-up** card shows every item set up, and the **Costs** tab's "Daily tidy-up" shows a run within a day
   of `CRON_SECRET` being set.

## Switching off and rolling back

- **One capability**: set its `WVR_CAP_…` switch to anything but `on`, then redeploy.
- **Every paid call at once**: `WVR_ENABLED=0`, then redeploy.
- **The API code**: in Vercel, promote the previous production deployment (instant rollback).
- **The pages**: in Cloudflare Pages, roll back to the previous deployment.
- **Git**: revert the commit and push. Never force-push.
